# Qyunslation 中英医药翻译工作台 UI/UX（SK-Q010）

本 Skill 约束 Qyunslation 线上版界面设计与实现。产品定位是**中英双语、医药研发、复杂文档保真翻译与审校工作台**，不是通用多语种聊天翻译器，也不是软件字符串本地化平台。

## 边界

- 本 Skill 负责信息架构、交互、组件、状态表达、响应式、无障碍和界面验收。
- 翻译质量、文档结构识别、图片重绘和版式算法由对应 Skill/计划负责；本 Skill 消费它们输出的 Manifest、状态和问题对象。
- 不复制竞品代码、品牌、文案或受保护视觉资产；只吸收可验证的交互模式。

## 铁律

1. **先确认真实运行界面，再改代码。** 当前生产服务可能由 `pdf2zh_next --gui` 与 `scripts/apply-pdf2zh-*.py` 补丁链提供，而仓库 `frontend/` 是另一套 Vue 界面。必须查服务入口、静态资源和补丁顺序；禁止在未被加载的前端上“完成”需求。
2. **文档画布是主角。** 原文/译文页面、当前对象和问题定位占主视区；上传设置、任务队列和高级参数都是辅助区。任何桌面宽度都不得裁掉译文栏。
3. **快速模式与专业模式共用一份任务。** 快速模式只露出文件、翻译方向、文档类型和主操作；专业模式按需展开对象审校、术语、翻译记忆、QA 与历史。禁止维护两套互不兼容的流程。
4. **只为中英双向优化。** 方向控件是清晰的“中→英 / 英→中”双态开关；自动检测只能提出建议，必须显示最终采用的源语言。不要用庞大语言下拉框稀释主任务。
5. **Manifest 是界面事实源。** 页数、Figure/Table/图片数量、版式、对象 ID、跳过区域、问题和能力状态均来自结构 Manifest；禁止解析日志、文件名或 DOM 猜计数。
6. **预扫描与翻译使用显式状态机。** 至少区分 `queued/scanning/translating/rendering/review_ready/succeeded/failed/cancelled/blocked/degraded`；未知、超时或截断不得显示成数字 `0` 或“已完成”。
7. **双语联动按页和对象锚点。** 同步导航使用 `page_id/object_id`；百分比滚动只能做降级方案。旋转页、跨页表、重排版和不同页高不能依赖相同滚动比例。
8. **原文不可变，译文可追溯。** 所有编辑只作用于目标对象并保留版本/恢复能力。参考文献区（含章节标题、条目、文章标题与链接）按策略整区原样保留，并在界面解释“为何跳过”。
9. **对象类型决定编辑器。** 正文/标题、表格单元格、图片 OCR 文本、题注、脚注分别使用适配的编辑与预览；表格脚注和图片文字不能被隐藏在普通段落列表里。
10. **质量问题必须可见、可定位、可处置。** 术语、数字/剂量、漏译、格式、字体溢出、表格/图片未译、参考文献误译分为警告与阻断；每条问题可一键跳到对象，并支持解决、忽略和记录理由。
11. **默认不展示原始日志。** 用户先看到阶段、页码、对象、耗时和可执行建议；诊断日志放入可复制的“技术详情”，不能占据主工作区。
12. **遵守统一设计系统与无障碍。** 语义化控件、可见 `focus-visible`、键盘完整操作、足够对比度、44px 触控目标、文本标签优先；不得用无标签图标或 `outline: none` 破坏可发现性。
13. **响应式不是缩小桌面。** `>=1440px` 可三栏；`1024–1439px` 双画布加抽屉检查器；`768–1023px` 原/译文切换；`<768px` 单画布、底部主操作和全屏抽屉。任何断点都不得横向溢出。
14. **长任务可恢复。** 刷新、断线、切文档和代际更新后，界面从服务端任务状态恢复；旧任务回调不得覆盖新任务，取消/重试必须幂等。
15. **用真实复杂样本验收。** 至少覆盖单栏、双栏、多栏、旋转表、图片 OCR、表格脚注、纯图片页、参考文献、失败/截断和缓存命中；只在空白占位样本上通过不算完成。

## 产品架构纲领

采用“**文档画布 + CAT 审校侧栏**”混合架构：

```text
应用栏：文档名｜中英方向｜任务状态｜帮助/账户
左侧工作坞：上传/文档队列｜基本选项｜预扫描摘要｜主操作
中央主画布：原文页 ⇄ 译文页｜页缩略图｜缩放/旋转/同步｜对象选中
右侧检查器：译文编辑｜术语/TM 建议｜QA 问题｜历史（专业模式）
```

快速翻译用户只需经过“上传 → 预扫描确认 → 翻译 → 下载”；专业用户在相同任务中进入对象级审校。完整信息架构见 `references/workbench-architecture.md`。

## 标准施工流程

1. **定位运行时**：确认当前服务入口、实际 DOM/资源来源、补丁链和最终覆盖者。
2. **建立基线**：在目标视口和真实样本上截图，记录用户任务、Manifest、网络/控制台和现有缺陷。
3. **选择纵切面**：入口、任务、画布、检查器、设置中一次只交付一个可闭环流程。
4. **先定状态契约**：列出后端字段、Manifest 字段、加载/空/失败/降级状态，禁止组件自行推断。
5. **复用组件与令牌**：不新增平行设计系统；复杂组件按状态、视图、适配器拆分。
6. **实现键盘与窄屏路径**：不能在桌面视觉完成后再补。
7. **跑自动与人工门禁**：按 `references/acceptance-gates.md` 记录证据；检查真实运行时而不只检查源码。
8. **回写规范**：新增稳定规则进本 Skill；一次性过程和证据进入对应 WT。

## 当前代码基线提醒

- `frontend/src/App.vue` 是 Vue 3/Tailwind 工作台；`scripts/pdf2zh.service` 则可能启动 Gradio 上游界面。二者需先辨真伪。
- `frontend/src/style.css` 当前移除了按钮焦点轮廓；修界面时必须恢复可见焦点。
- `PreviewOffcanvas`、底部图标按钮、原始日志主视图和按百分比同步滚动均是待替换模式，不应继续扩展。
- Bootstrap 兼容类、Tailwind、行内样式和散落色值并存；新增界面只能落到统一令牌层。

## 完成定义

- 用户能在目标断点完成上传、预扫描、翻译、审校、下载，不依赖技术日志。
- Figure/Table/图片/页数与 Manifest 一致；阻塞、截断和未知状态不会伪装成成功。
- 原文只读且清晰；译文对象可定位、可编辑、可撤销；参考文献策略可解释。
- 表格、图片和脚注有专用审校入口；QA 可跳转到具体页/对象。
- 键盘、焦点、屏幕阅读器名称、对比度和响应式门禁通过。
- 已在真实提供服务的界面验证，并留下截图、状态和自动化结果。
