# 踩坑（SK-Q010）

本文件是 Qyunslation UI/UX 踩坑 SSOT。一次性过程写 WT，稳定教训归并到这里。

1. **改错前端。** 生产可能运行 `pdf2zh_next --gui` 加补丁，而不是 `frontend/` 的 Vue 应用。只看源码截图或本地 Vite 通过不能证明线上生效。
2. **补丁顺序覆盖。** 多个 `apply-pdf2zh-*.py` 修改同一 `gui.py` 时，后执行者会静默抹掉前一补丁。新界面必须验证最终服务产物，而不是单个补丁文件。
3. **把技术日志当进度。** 原始日志对开发有用，但会让普通用户无法判断还需多久、哪里失败、下一步做什么。主界面必须用阶段和对象状态。
4. **用 `0` 伪装未知。** 扫描超时、截断或不支持时显示 0 Figure/Table，会被理解为完整识别。必须显示待确认、截断或阻断。
5. **从底层图片资源计 Figure。** 一个 Figure 可由多张 xref/蒙版/矢量组成；资源数不是语义图数。只消费 Manifest 对象。
6. **按滚动百分比同步。** 原译文页高、重排、旋转和跨页表不同，百分比很快漂移。页/对象锚点是主路径。
7. **在窄屏硬塞双栏。** 结果是两边都看不清、译文标题被裁。空间不足时切单画布并保留快速对照。
8. **全局移除焦点。** `outline: none` 让键盘用户看不到位置。只能以更清晰的 `focus-visible` 替代，不能删除。
9. **无标签图标。** 固定底栏的下载/预览图标即使有 tooltip，触屏和新用户仍难发现。核心动作使用文字或图标+文字。
10. **设计系统继续分叉。** Bootstrap 兼容类、Tailwind、行内样式和硬编码色值并存时，新增“临时修复”会让响应式和主题更脆弱。先建语义令牌与组件边界。
11. **把预览藏在 offcanvas。** 文档翻译的价值是原译文页面；把它作为次级弹层会让任务卡/日志反客为主。
12. **让高级设置主导首屏。** 模型、OCR、并发、缓存和 PDF 内核是实现细节。默认自动策略，只有诊断或专家需要时才展开。
13. **把 CAT 网格设为默认。** Smartcat/MateCat 的密集分段适合职业译者，却会压垮只想上传下载的用户。专业模式按需开启，且保留页面上下文。
14. **静默保护参考文献。** 不翻译是正确策略，但若不显示保护范围和原因，用户会误判漏译；边界不确定时必须要求确认。
15. **缩小字体掩盖溢出。** 图片/表格译文过长时无限缩字会制造不可读结果。应先重排、改换行/缩写策略，再把无法解决的对象列为 QA。
16. **原文和译文共用可变资产。** 图片回写若覆盖源文件，无法审校和恢复。原文永远只读，译文派生物按任务代际存储。
17. **信任文件名、错误文本或 iframe。** 上传内容和后端消息都可能不可信；直接写入 HTML/srcdoc 会带来注入和隐私风险。
18. **只用漂亮演示样本。** 简单单栏论文会掩盖旋转表、图片 OCR、跨页对象、长术语、参考文献和失败状态问题；必须跑真实样本矩阵。
