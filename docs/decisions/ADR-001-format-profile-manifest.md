# ADR-001：以跨格式结构清单作为原位翻译唯一事实源

## 状态

Accepted

## 日期

2026-09-07

## 背景

当前 PDF、DOCX、图片和 PPTX 分别使用预扫描结果、图片翻译清单或 Office 对象遍历，用户可见的“插图数”甚至由位图候选数与矢量区域数直接相加。格式支持也分散在 GUI、预扫描、服务端自动路由和具体工作流中，导致同一后缀在不同阶段得到不同结论。

系统需要同时支持多种容器与内容题材，并让预扫描、执行、UI 和验收对同一批语义对象逐项对账。继续扩充条件分支会放大漂移，且无法可靠表达原生可编辑与图片化产物的差异。

## 决策

### 1. 建立 Manifest v1 SSOT

新增版本化 `DocumentStructureManifest`，描述输入身份、格式能力、内容画像、处理模式、画布、语义对象、问题和派生摘要。后续扫描器只生产该合同，翻译执行器、UI 和验收只消费该合同或其明确适配器。

现有 `Tier1Result`、`Tier3Result`、`PdfImgManifest`、DOCX `OverlayManifest` 和 `.graphics.json` 暂不删除；迁移期间通过 adapter 写入或映射到 Manifest v1。

### 2. 分离四个维度

- `source_format` 表示实际容器或编码。
- `content_profile` 表示内容结构先验。
- `processing_mode` 表示原生、图片化或混合处理策略。
- runtime capability 表示当前环境是否具备解码器、转换器、字体和渲染器。

任何维度都不得由另一个维度隐式替代。文件是 PDF 不代表它是论文；内容是 Poster 也不代表它必须是图片。

### 3. 产品要求与机器能力分离

格式注册表使用 `CORE / NORMALIZE / CONDITIONAL / UNSUPPORTED` 表达产品承诺，运行探针使用 `AVAILABLE / DEGRADED / UNAVAILABLE / UNKNOWN` 表达当前环境。未知格式必须 fail-fast，不能回退成 TXT 或在执行中途才失败。

### 4. 原生与图片化均为正式模式

DOCX/PPTX 优先保留可编辑对象；复杂幻灯片、图片型 PPT 和 Poster 可选择图片化。图片化产物必须标注 `editable=false`，保留来源、转换器、DPI、字体环境和每页 hash，不得伪装成可编辑输出。

### 5. 身份、坐标和错误可机读

- 文档身份使用完整文件 SHA-256；快速截断 hash 只用于缓存提示。
- `object_id` 与可读 `semantic_id` 分离，Figure/Table 主计数由语义对象派生。
- canonical 坐标统一左上原点并显式携带单位、画布尺寸和旋转；原生坐标保存在 `source_geometry`。
- 状态和问题使用稳定枚举/错误码；业务消费者不得解析人类文案做决策。

### 6. 兼容策略

Manifest 使用语义版本。相同 major 只做向后兼容的可选扩展；未知 major 返回 `MANIFEST_VERSION_UNSUPPORTED`。实验性 detector 数据进入 `evidence` 或 `extensions`，不随意扩充顶层合同。

## 备选方案

### 继续扩充现有预扫描结构

拒绝。它以 PDF/图片候选为中心，无法自然表达 Office shape、自由布局画布、转换血缘和多格式能力。

### 每种格式保留独立 manifest

拒绝。格式内部实现可以独立，但 UI、执行和验收需要跨格式的公共身份、状态与错误语义；多个公开合同会继续产生计数和状态漂移。

### 所有输入先转 PDF 或图片

拒绝作为默认方案。它会破坏 DOCX/PPTX 可编辑性和原生表格/文本语义。图片化仅作为显式正式模式或受控降级。

### 只按扩展名决定工作流

拒绝。扩展名可能伪造，也无法反映运行依赖是否可用；必须结合 MIME/魔数与能力探针。

## 后果

### 正面

- 用户计数、执行对象和最终审计可以一一对应。
- PDF、DOCX、图片、PPT/PPTX 能共享稳定边界，同时保留各自实现细节。
- 格式扩展与题材扩展可独立进行。
- 失败、截断和降级不再伪装成“0 个对象”或成功。

### 成本

- 需要为旧局部清单编写适配器并维护一个迁移周期。
- Schema 变更必须经过兼容审查和契约测试。
- 金标、转换器版本和渲染环境需要持续维护。

## 迁移

1. 030a 只新增合同、注册表和测试，不接入生产。
2. 030b 建立格式探测、能力探针和输入归一化。
3. 030c 让统一扫描器生产 Manifest v1，并为旧结果提供 adapter。
4. 030d–030g 按格式迁移执行器。
5. 030i 完成 UI 切换、旧合同弃用与发布门禁。

## 回滚

030a 为纯新增且未接线；可移除 `qyunslation.structure`、对应合同/测试和本 ADR。生产行为不会变化。后续接线阶段按 adapter 和消费者分别回滚，旧清单在迁移完成前保留。
