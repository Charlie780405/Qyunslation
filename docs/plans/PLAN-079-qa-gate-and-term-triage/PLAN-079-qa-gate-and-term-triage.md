## 1. 目标与非目标

**目标**

1. 点击 QA 问题的“在对照视图定位”后，用户确实看到对应文档页，同页重复点击也有反馈。
2. 正式稿只被**高置信度、会实质影响内容正确性、完整性或安全性**的缺陷阻断。
3. 术语库治理（某个词是否收进共享词库）与本文交付（这篇译文能否发出）解耦：常见、稳定、低风险的词不要求逐条人工审核，处理本文的术语问题也不需要写共享词库。
4. “检查没跑成”和“译文有问题”在门禁原因、计数和界面上可以区分。
5. 收口 PLAN-077 与 PLAN-078 的上线遗留：每一项要么已验证完成，要么有明确的执行方和决策点（§6.F）。

**非目标**

- 不以减少 QA 条数为目标；目标是减少误报造成的交付阻塞，同时保留高风险问题的可追溯性。
- 不改动剂量/频次/数字/否定等关键事实规则的阈值（除非阶段 B 的标注回放给出证据）。
- 不做词/句级坐标定位；本计划只承诺页级定位。
- 不重做 078b 已交付的处置模型（C1–C4/W/I、第二人确认、理由、审计），只复用。
- 不在本计划内迁移对象存储或 Authentik runtime（F15、F16 只做证据和决策）。

## 3. 现状证据（静态追踪）

### 3.1 对照视图定位

- `RunDetailPage.vue` 中各块的渲染顺序为 QA 待办 → 阶段事件 → 术语面板（每页最多 40 行）→ 对照查看器。`locateAnchor` 只执行 `view.setPage(anchor.page)`（`RunDetailPage.vue:468-469`），即 `router.replace` 改 URL 页码。
- 查看器内部会滚到目标页（`watch(props.page)` → `scrollAll`），但整个查看器在视口外，用户看不到变化。
- 同页重复点击：路由不变 → watch 不触发 → 没有任何响应。
- `anchor.side` 未使用；平板/手机布局下只显示 `activeSide` 一侧。
- 两栏共用一个页码。原译页数不同（`PAGE_COUNT_MISMATCH`）时，按译文页码定位，源文栏也会跳到同号页，可能误导用户。
- 测试只断言 `query.page === '3'`（`__tests__/qaTodoPanel.test.js:189-194`）。

### 3.2 术语与门禁

- `_formal_gate` / `_build_list_context` 把本任务所有状态不在 `approved/rejected/applied` 的候选视为未决（`v1.py:2257, 2288-2296, 2332-2340`），非空即 `unresolved_terms`。`pending`、`pending_admin`、`violation` 三种状态混在一起计数。
- `violation` 的含义是“词库硬约束译名在本段未被使用”（`workbench/bridge.py:254-290, 370-392`），属于真实的文档缺陷信号；`pending` 只表示“发现了一个词”。两者被同等对待。
- 结构化抽取提示词允许抽取“量表/终点/方法”（`term_extract.py:271-276`）。模型路径产生的 `term_type` 是自由文本，`sensitivity analysis` 这类统计方法会以 `risk=normal, status=pending` 入库，然后阻断门禁。
- API 文案称“通用词、统计词……不进入新候选”（`v1.py:5996`），实际只排除了 denylist 中的统计缩写（OR/HR/CI…），不含统计方法短语。
- 已在运行时词库中的词会被跳过（`term_extract.py:671-672`），所以 v1 所说的“直接复用”已部分实现，不需要新开发。

### 3.3 乱码检测

- `detect_text_artifacts()`：U+FFFD、`[\x00-\x08\x0b\x0c\x0e-\x1f\x7f-\x9f]`、`Ã.|Â.|â€…` 任一命中即 `TEXT_ENCODING_ARTIFACT`（`structure/text_sanitize.py:24-25, 150-158`），在注册表中为 C1（不可授权例外，只能修复或经第二人确认误报）。
- 检测对象是从渲染后 PDF 重新抽取的文本，不是翻译引擎输出的字符串，因此无法区分“译文字符串损坏”“字体缺少 ToUnicode 导致抽取异常”和“源文 PDF 本来就有”。
- 每种代码只生成一个 QA 条目，页锚点最多 5 页，没有码点或检测器明细。

## 4. 严重度与处置原则

严重度说明风险，处置状态说明问题当前的处理进度，规则类别决定谁能怎么处理。三者相互独立。候选数量和检查器故障都不直接折算成 blocker。

| 级别 | 判断原则 | 典型情况 | 对正式稿的影响 |
| --- | --- | --- | --- |
| 阻断（C1） | 有高置信度证据表明译文缺失、损坏，或关键含义/身份标识被改变 | 空译文；**已确认**的可见乱码或 IL 标记；申报编号或联系方式丢失/改写 | 阻止批准；只能修复，或由第二人确认规则误报 |
| 阻断（C4 术语） | 与已批准词库发生确定冲突，或高风险术语存在有证据的歧义 | `TERM_HIGH_RISK_CONFLICT`、`TERM_FORBIDDEN_TARGET`、`TERM_TARGET_MISSING`、新增 `TERM_REVIEW_REQUIRED` | 阻止批准；修复，或由复核人写理由授权例外（078b 规则） |
| 警告 | 可信度或影响有限 | 普通英文残留、疑似乱码但未确认可见、页数/版式差异、未校准的剂量/频次差异 | 不阻止；可确认已阅，留审计 |
| 信息 | 不表示缺陷 | 取证摘要、已复用的批准译名 | 不影响 |
| 检查未完成（C3） | 检查没有成功运行，不能据此判断译文 | QA 超时、输入不可读、术语模型不可用、语义检查降级 | 显示“未验证/待重试”，单独计数；能否批准由 D1 决定 |

剂量/频次的文档级比较曾出现明显的格式差异误报，继续按警告处理；只有回放证明召回率和误报率达标后，才讨论升级。

## 5. 术语处理设计

### 5.1 三类对象，三条通道

| 对象 | 存放 | 谁处理 | 是否影响本文交付 |
| --- | --- | --- | --- |
| 词库积累候选（“发现了一个专业词”） | `document_term_candidate` | 术语管理员在术语工作台批量整理 | **否** |
| 本文术语缺陷（与批准词库冲突、禁用译法、硬约束未应用） | QA 条目 C4（已有码） | 复核人：修复或授权例外 | 是 |
| 本文术语风险（高风险且有歧义证据，但没有批准译名） | QA 条目 C4 `TERM_REVIEW_REQUIRED`（新码） | 复核人：确认本文译法，或写理由授权例外 | 是（D2 可选择降为警告） |

推荐设计：**门禁只读 QA 条目**（`qa_summary.open_blocker`），不再读候选表。理由：

- 078b 已有处置、第二人确认、理由下限、指纹、规则集版本、跨轮次差异、列表与详情同源计数，不必重写一套；
- 本文处置不写共享词库，也不进抑制索引；
- 候选表不需要新增高频查询字段，避免对 JSON 列做门禁查询。

### 5.2 默认处理顺序

1. **直接复用**：命中运行时词库的词，不生成候选（已实现）。
2. **不进候选**：通用表达、统计方法和常见学术搭配、词形碎片、人名/机构名/按策略保留的单位名、用户明确要求保留原文的项目。为统计方法在 `term-candidate-rules.toml` 中新增 `[exclude] phrase_denylist`（可审查、带版本），覆盖模型路径和确定性路径。`sensitivity analysis` 作为第一条回归样本。
3. **候选，不阻断**：其余值得入库的新词照常进入候选表，在术语工作台可见，不影响交付。
4. **生成 `TERM_REVIEW_REQUIRED`**：满足 §5.3 的条件。
5. **词库裁决与本文交付分离**：在术语工作台批准或驳回候选，只影响词库；本文的 QA 条目在下次复检时按新词库重新判定。

### 5.3 `TERM_REVIEW_REQUIRED` 的生成条件（初版，阶段 B 校准）

只有以下**必要条件**和**至少一个证据条件**同时满足，才生成：

- 必要条件：`term_type ∈ {drug, biologic, target, disease_subtype, safety_event, endpoint, scale, protocol}`，且未命中批准词库（单纯的未知缩写不算）。
- 证据条件（只用阶段 B 确认能可靠计算的信号）：
  - a. 同一 `source_norm` 在本文中出现 ≥2 种不同的译法（需要段落对齐；能否复用 `workbench/term_align.py` 由阶段 B 确认）；
  - b. 源文出现该词，但对应译文段落中既没有译名，也没有保留原文（漏译信号）；
  - c. 与另一个已批准概念的别名冲突（同一原文、不同批准译名）。

如果阶段 B 证明 a/b 不能可靠计算，初版只上线 c，并在 §10 的待验证假设中记录。每条 `TERM_REVIEW_REQUIRED` 的证据都必须包含原文位置、所在段落的译文摘录和触发条件码，`identity_keys=("source_norm", "signal")`，保证跨轮次指纹稳定。
