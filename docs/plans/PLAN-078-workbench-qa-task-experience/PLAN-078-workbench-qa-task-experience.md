## 1. 目标

1. 让 QA 阻断**可理解、可定位、可处理、可复检**。用户能看懂“还剩什么、下一步做什么”。不降低检查标准，也不用删记录或清零计数的方式伪装通过。
2. 让任务状态单一可信：执行、质量处理、复核、交付资格各自独立表达，不再出现“翻译中”却已无执行器的情况。
3. 每次启动翻译前确认最终参数。确认内容、请求、服务端解析、执行器配置和冻结快照五者一致。
4. 最近任务支持服务端检索、分页、改名、版本归组、批量归档/恢复，以及可恢复删除（回收站）。
5. 修掉列表静默失败、拖放无效、过度轮询、原生对话框等影响效率的问题。

### 2.1 样本统计【跑】

| 阻断代码（按任务数） | `AD_NUMBER_DRIFT` 5；`AUTHOR_METADATA_CHANGED` 1；`TERM_HIGH_RISK_CONFLICT` 1；`TEXT_ENCODING_ARTIFACT` 1（共 2 条） |
| 格式/领域/方向 | `AD_NUMBER_DRIFT` 全部来自 AD docx（英→中 3 个、中→英 2 个）；其余阻断来自同一个通用 PDF |

| 规则版本 | 39 条为 `076-qa-v1`，**7 条为空**；空值全部来自同一个 PDF 任务，与 requalify 路径不写 `rule_version` 吻合（§3 Q7） |

### 2.2 六类原因对照

| 类别 | 样本或代码中的表现 | 结论 |
| --- | --- | --- |
| 真实质量问题 | `AD_NUMBER_DRIFT` 只缺不增，`TEXT_ENCODING_ARTIFACT` | 【假】很可能有一部分是真实漏译或乱码，需授权人员看证据核对，见 H9 |
| 规则误报 | `AUTHOR_METADATA_CHANGED` 按整行精确匹配（`pdf_inspect.py:86-113`）；术语目标按子串匹配，没有压缩空白（`term_snapshot.py:145`）；`LOGO_MISSING` 用首页图片字节哈希比较（`pdf_inspect.py:309-323`） | 【假】三条规则都可能被 PDF 换行或图片重编码触发，需用金标样本离线回放，见 H7/H8 |
| QA 服务不可用 | 术语模型不可用时直接产生 **blocker** `TERM_EXTRACTION_DEGRADED`（`v1.py:1400-1410`，`term_extract.py:543-557`）；机密资料不配置术语模型（`term_extract.py:366-371`） | 【码】服务可用性被当成质量阻断；【跑】测试红灯也来自这里 |
| 产物缺失 | `QA_INPUT_UNAVAILABLE` 是 warning，`AD_QA_SOURCE_UNAVAILABLE` 是 blocker | 【码】同一类原因严重度不一致 |
| 状态错误 | 5 个 `qa_blocked` 中 4 个被心跳过期改成 `interrupted`；`request_changes` 后任务停在假“翻译中” | 【跑】+【码】，见 Q1–Q3 |
| 旧结果残留 | requalify 先删本代 QA 再重建（`v1.py:3140-3143`）；术语门禁不按 generation 过滤（`v1.py:1610-1618`） | 【码】没有历史，也无法对比 |

### 2.3 判断

从现有证据看，“经常卡在 QA”主要不是检查太严，而是以下四个缺口叠加：

1. **没有处理路径**【码】。QA 项是只读的。`qa_item.resolved`/`reviewer_note` 字段存在（`models.py:362-363`），但没有任何接口写入。唯一的“修复”是整篇重试，而重试要求预检未过 24 小时（`v1.py:86`、`:3053`）。
2. **状态把用户带错方向**【码】【跑】。执行完成后 `status` 仍写成 `translating`（`v1.py:1497`、`:1581`），前端据此显示进度动画并只提供“取消”。Office 任务的心跳过期后又被改成 `interrupted`，界面只剩“续跑”，而续跑会重新翻译。
3. **无法定位**【跑】。阻断项全部来自全文级规则，`object_id` 为空，检查器显示“—”。
4. **服务故障冒充质量问题**【码】【跑】。术语抽取模型不可用时直接阻断，修译文没用，复检也没用。

因此本计划**不整体降低阈值**。先修状态和处理路径，再按 H7–H9 用样本逐条校准规则。

## 5. 状态模型与权限矩阵

### 5.1 生命周期（服务端派生 `lifecycle` 字段，前端只消费）

| lifecycle | 数据来源 | 中文 | 是否轮询 |
| --- | --- | --- | --- |
| `executing` | `status ∈ {queued,scanning,translating,rendering}` | 执行中 | 是 |
| `qa_checking` | `status=gated` 且最新检查轮次 `running` | 正在检查 | 是 |
| `qa_action` | `gated + qa_blocked` | 待处理质量问题 | 否 |
| `qa_unavailable` | `gated + qa_unavailable` | 质量检查未完成 | 否 |
| `review` | `gated + review_ready/qa_degraded` | 待人工复核 | 否 |
| `changes_requested` | `gated + changes_requested` | 已退回修改 | 否 |
| `failed` | `failed/blocked/degraded` | 失败 | 否 |
| `interrupted` | `interrupted` | 已中断 | 否 |
| `cancelled` | `cancelled` | 已取消 | 否 |
| `completed` | `succeeded + approved/legacy_unverified` | 已完成 | 否 |
| 正交标记 | `superseded_by`、`archived_at`、`deleted_at` | 已被新版本取代、已归档、回收站 | — |

主要状态转换：`executing → gated(qa_checking) → qa_action | qa_unavailable | review`；`qa_action → qa_checking`（复检或授权例外后重算）；`qa_action/review/changes_requested → 新版本 executing`（旧版本 `superseded`）；`review → completed | changes_requested | failed(reject)`；`executing → cancelled | failed | interrupted`；`interrupted → executing`（同代续跑，冻结配置）。
