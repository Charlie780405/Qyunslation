# PLAN-068：预检提速、任务生命周期与语言选择

## 背景与目标

当前工作台把大文件上传、校验和预检都表现为一个“正在预检”状态；用户无法判断是在上传还是分析。历史任务只有列表、取消和重试，缺少归档、恢复和删除；语言方向藏在高级参数中，开始翻译前缺乏明确的目标语言确认。

本计划在不改变现有 `TranslationRun` 执行器边界的前提下，完成三个垂直切片：

1. 用流式暂存和轻量预检减少内存复制及不必要等待，并在 UI 区分上传/分析阶段。
2. 为任务增加可审计的归档、恢复、重命名和终态删除能力；运行中的任务必须先取消，不能被直接删除。
3. 将源语言/目标语言提升为翻译前的显式必选项，服务端校验并写入预检建议与任务参数快照。

## 冻结决策

- 本阶段正式验收语言对仍为 English ↔ 简体中文；不伪装支持未实现的语言。
- 目标语言不允许为空，也不能与源语言相同；旧 `direction` 字段继续兼容机器调用。
- 上传预检不启动翻译；只有用户确认语言、文档类型和预检结果后才创建 `TranslationRun`。
- 预检通过 SHA-256 去重：同租户、同操作者、同文件摘要且仍在 TTL 内时复用既有预检记录，不重复保留正式暂存或分析。
- 归档是软状态，默认列表隐藏归档任务；恢复不会重启任务。
- 删除只允许终态任务；删除任务前清理其 artifact 文件。若该预检不再被其它 generation 引用，同时清理暂存文件和预检记录。
- 运行中的任务只能取消，取消完成后才可删除；服务端不得接受前端绕过。
- 任务名称是显示字段，原始文件名仍作为不可变来源证据保存。

## 接口契约增量

### 语言与预检

- `POST /api/v1/preflights` 增加可选表单字段 `source_language`、`target_language`；旧 `direction` 仍可用。
- `Preflight` 增加 `source_language`、`target_language` 和 `reused`。
- 同租户相同 SHA-256 且未过期的预检返回已有记录，HTTP 仍为 `201` 以兼容当前客户端，响应 `reused=true`。

### 任务生命周期

- `GET /api/v1/translation-runs?include_archived=false&status=&page_size=`：默认不返回归档任务。
- `GET /api/v1/translation-runs/{runId}`：返回 `archived`、`display_name`、源/目标语言。
- `PATCH /api/v1/translation-runs/{runId}`：允许修改 `display_name` 和 `archived`；不允许修改运行参数。
- `POST /api/v1/translation-runs/{runId}/restore`：恢复归档任务（可选便利端点，内部与 PATCH 一致）。
- `DELETE /api/v1/translation-runs/{runId}`：仅终态可删除，运行中返回 `409`；幂等删除返回 `204`。
- 所有变更写审计事件，且继续执行租户、角色和 actor 边界。

统一错误仍采用现有 HTTP + `detail` 兼容结构；新增机器码放入 `code` 时不破坏旧客户端。

## 详细开发任务

### 068a：流式预检与复用

- 将 `_read_upload_limited` 改为分块写入租户隔离的临时文件，同时计算 SHA-256；成功后原子改名，失败清理临时文件。
- 以 `(tenant_id, actor_sub, source_sha256, expires_at)` 查询可复用的 ready 预检；复用前验证暂存文件仍存在且大小一致。
- 预检状态在响应中区分 `uploaded`、`analyzing`、`ready`、`blocked`、`failed`；本阶段轻量格式校验完成后直接 ready，不调用翻译引擎。
- 保留 TTL 清理策略，禁止用用户文件名参与路径拼接。
- 测试 61.9MB 等大文件、超限、断写清理、同摘要复用、跨租户不可复用。

验收：上传内存不随文件大小线性增长；重复上传返回 `reused=true`；所有旧预检 API 测试保持通过。

### 068b：任务生命周期 API

- 给 `translation_run_record` 增加 `display_name`、`archived_at`、`archived_by` 字段及索引/迁移。
- 给响应增加 `archived`、`display_name`、`source_language`、`target_language`。
- 实现 PATCH、restore、DELETE；DELETE 清理 artifacts，且只对终态任务开放。
- 归档/恢复/改名/删除写审计；管理员可管理租户内任务，但不能跨租户。
- 同一 preflight 有多个 generation 时，删除某一 run 不误删仍在使用的暂存源文件。

验收：普通用户只能管理自己的任务；管理员按现有角色规则管理租户任务；活动任务不能删除；删除后下载接口返回 404。

### 068c：翻译前语言选择

- 前端上传区直接显示“源语言”和“目标语言”，不再把关键选择藏在高级设置中。
- 正式选项为“English”和“简体中文”；选择相同语言时禁用开始预检/翻译并显示原因。
- 上传预检、创建任务、重试均使用同一语言快照；重试不读取后来改变的个人默认值。
- 后端兼容旧 `direction`，但新请求优先验证 source/target 对；拒绝未支持语言组合。

验收：创建任务请求明确包含 source/target；任务详情和列表显示语言对；旧 API 仅传 direction 仍通过。

### 068d：工作台 UI

- 上传按钮状态拆成“上传中 x%”“正在检查文件”“预检完成”。
- 最近任务增加筛选：进行中、已完成、已归档；提供归档/恢复、重命名、删除操作。
- 删除必须二次确认；活动任务只显示取消，不显示删除。
- 归档任务默认不占主列表空间；用户可展开“已归档”。
- 任务行展示 `English → 简体中文`、名称和原始文件名，保留 artifact 下载。
- 任务轮询只轮询未归档活动任务；删除/归档操作使用请求取消和乐观刷新。

验收：刷新后筛选和归档状态保持；操作失败显示结构化错误；键盘和 44px 触控区域不退化。

### 068e：验收与发布

- 后端单测/API 契约测试覆盖上传、复用、语言校验、CRUD、并发冲突和租户边界。
- 前端单测覆盖阶段文案、语言组合、删除确认、归档筛选和轮询 generation。
- 运行类型检查、构建、UI 测试和迁移升级/降级测试。
- 生产发布前验证 `/next/login`、`/next/workbench`、API 健康、静态资源和一个真实小文件预检。
- 若预检速度改善不足，下一阶段再引入浏览器 SHA-256 + 摘要探测接口；本阶段不把昂贵 OCR 放进同步上传请求。

## 性能目标

- 上传阶段内存峰值不因 `bytes` 双份复制而翻倍。
- 已有 SHA 的重复文件不重复写入或分析。
- 10MB 以下文本/PDF 的预检服务端处理目标 < 1 秒（不含网络上传）。
- 61.9MB 文件预检的用户反馈至少显示真实上传进度，不再长时间停留在单一“正在预检”。

## 风险与回滚

| 风险 | 缓解 |
|---|---|
| 数据库迁移中断 | 新字段 nullable，先迁移再启用 UI；可降级到旧列表 |
| 删除误操作 | 默认归档、二次确认、终态限制；artifact 删除前校验租户 |
| 旧机器调用只传 direction | 保留兼容解析，不破坏旧 Bearer API |
| 大文件上传中断 | 临时文件 + 原子 rename + 失败清理 |
| 预检复用错误 | 摘要、大小、TTL 和租户四重校验 |

## 交付门槛

- 068a–068c 的 API 契约和迁移测试通过后再接入 UI。
- 068d 完成后，工作台可选择语言、上传、预检、创建任务、归档/恢复/删除。
- 068e 完成后才部署生产；旧任务、旧下载和 Gradio 回退入口不受破坏。
