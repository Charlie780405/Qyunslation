## 1. 背景

PLAN-079 的第一版上线后，用户在生产环境反馈了以下问题：

1. 乱码类阻断只能由反馈人之外的第二人确认，单人使用时永远清不掉。
2. 术语候选过多（一篇文献超过 100 条），审核负担重。
3. 阻断项的解决方案只是一段文字和动作名，操作路径不清楚。
4. 点击“我核对过，这是检查误报”后阻断没有清除，界面也没有说明卡在哪里。
5. 同一误报在重新生成修订版后要再确认一次。
6. 批准正式稿后没有导出入口，退出 QA 页才能找到。

## 2. 目标

- 单人可以按规则处理非关键事实类的阻断，每次处置仍记入审计。
- 普通术语候选不阻断交付；与批准译名的真实冲突仍阻断。
- 每个阻断项都给出可执行的解决方案，并按账号权限过滤。
- 批准后直接进入导出页，并能回到 QA 页修改、生成修订版。

## 4. 决策与风险

以下为 WT-079 中记录的用户选择，风险需要持续跟踪：

- **乱码放行单人化（087b）。** 乱码改为 C2 后，复核人一人即可授权例外。数字、否定、剂量、编号等其他关键事实类仍是 C1，需要第二人确认。风险：乱码放行没有第二人把关。
- **跳过影子观察期（087b）。** 门禁直接切换为 `enforce`，没有经过一周影子观察。当时只用了一个任务作样本。风险：普通候选的误阻断与漏放仍需观察。
- **自我确认（087d）。** 术语管理员、管理员、所有者可以确认自己提交的误报，审计中标注 `self_review`。风险：关键事实类的误报可由同一人放行。收紧的办法是把 `_apply_disposition` 中的 `self_confirm` 分支改回拒绝。
- **缩写过滤（087b）。** 只出现一次且原文无定义的大写缩写不再列为候选。风险：少列部分缩写，它们在后续任务中重复出现时仍会被列出。
- **“沿用”不静默继承（087e）。** 旧结论只作为预填项出现，每一项仍是单独的审计记录。
- **已批准版本可修订（087e）。** 生成修订版会产生新一代，旧版文件保留可下载。风险：使用者需要自行分清哪一版是当前版本。

## 8. 乱码与多余警告的根因修复（2026-10-21，用户授权）

**现象**：`50-LIT-2026-MGK10-Trial.pdf`（`a3887b13`）第 2 页因 `TEXT_ENCODING_ARTIFACT` 阻断，第 1 页有两条 `TEXT_ENCODING_INHERITED` 警告。页面上看到的 ■、• 字形本身正常。

**根因（已用源文件核实）**：源 PDF 两个符号子集字体没有 ToUnicode，code 1 按 cp1252 读成 U+0001，BabelDOC 把它当成文字送进翻译，译文文本层变成 U+FFFD。
- `AdvP4C4E74`：code 1 为实心圆点 •（第 2 页两处，项目符号）。
- `AdvMathpi6`：code 1 为实心方块 ■（第 1–11 页页眉分隔符）。
- 全文档 U+0001 只出现在这两个字体的 code 1 上，无其他用途。

**修法**：在 `qyunslation/structure/pdf_symbol_cmap.py` 的 `SYMBOL_FONT_FIXES` 中增加 `AdvP4C4E74: {1: "•"}`、`AdvMathpi6: {1: "■"}`。沿用现有修补机制（仅对无 ToUnicode 的字体生效，不改译文，不事后替换）。

**不做**：不放宽 QA 规则；不以授权例外放行；不改其他字体的映射；不改 `QYUNSLATION_ENCODING_INHERITANCE` 等开关。

**验收**：单元测试覆盖两条映射；用真实源文件跑 `fix_symbol_fonts_pdf`，确认第 1–2 页提取文本不再含 U+0001 / U+FFFD；重新翻译 `50-LIT` 后 QA 无 `TEXT_ENCODING_*` 条目，浏览器中两处符号可见。
