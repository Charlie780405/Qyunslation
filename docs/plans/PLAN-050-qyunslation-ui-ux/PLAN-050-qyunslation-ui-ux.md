# PLAN-050：Qyunslation 中英医药翻译工作台 UI/UX 总纲

> 状态：**完成**
> 日期：2026-09-13
> 前置：PLAN-030 多格式结构与原位翻译收口；PLAN-034 医药研发翻译 MVP；SK-Q010
> 目标分支：`feat/PLAN-050-qyunslation-ui-ux`
> 执行顺序：050a → 050b → 050c → 050d → 050e → 050f → 050g

## 一、目标

把 Qyunslation 从“配置、任务卡、原始日志和隐藏预览”升级为面向医药研发用户的中英双语文档翻译工作台：上传后先展示可信的结构摘要，翻译过程中明确阶段和问题，结果中以原文/译文页面为主，并允许对正文、表格、图片、题注和脚注进行对象级审校。

本计划只改界面、交互和界面状态接线，不重新发明 PDF/DOCX/PPTX/图片扫描算法。所有页数、Figure/Table、图片、参考文献保护范围和异常状态均消费现有 `DocumentStructureManifest` 与任务契约。

## 二、当前差距

1. 真实线上界面可能由 `scripts/pdf2zh.service` 启动的 `pdf2zh_next --gui` 与一组 `apply-pdf2zh-*.py` 补丁提供；仓库 `frontend/` 的 Vue 页面可能不是当前生产入口。修改前必须先完成运行时确认。
2. 当前预览被放在次级 offcanvas，任务卡和日志占据主空间，用户不能快速理解原文、译文和待处理问题。
3. 统计口径已经在 PLAN-030 固化为 Manifest 语义对象，但界面仍存在从底层资源、旧状态或日志派生计数的风险。
4. 单栏、双栏、多栏、旋转表、图片 OCR、表格脚注和参考文献保护没有形成统一的对象级交互。
5. 现有固定底部图标、隐藏焦点、混合 Bootstrap/Tailwind/行内样式和硬编码色值会降低可发现性、可访问性和响应式稳定性。
6. 300 DPI/高清预览、任务代际、截断/降级/阻断状态和断线恢复尚未以一套 UI 状态模型表达。

## 三、产品与架构决策

### 3.1 文档画布优先

桌面布局采用“左侧工作坞 + 中央原译文双画布 + 右侧对象检查器”。快速用户只经过上传、预扫描、翻译、下载；专业用户在同一任务中打开对象审校、术语、翻译记忆和 QA。

### 3.2 运行时单一事实源

050a 先回答“哪个界面正在被用户访问”。如果生产仍是 Gradio 补丁链，后续界面实现必须进入该链路；如果 Vue 已成为实际入口，才在 `frontend/` 实现。禁止两个 UI 同时演进却没有统一入口。

### 3.3 Manifest 驱动

Manifest 是页面、对象、计数、布局模式、参考文献保护、能力和问题的 SSOT。UI 不解析原始日志、不从 DOM 猜 Figure/Table 数量、不用 `0` 表示未知或截断。

### 3.4 原文保护与医药风险可见

原文始终只读。译文对象可以编辑、撤销和保留历史。参考文献区（含章节标题、条目和文章标题）按策略原样保留，并在界面显示保护原因。剂量、单位、数字、缩写、表格脚注和图中文字必须有可定位的 QA 结果。

### 3.5 中英双向优先

方向控件只提供“中文→英文 / 英文→中文”，自动检测仅为建议。模型、OCR、并发和缓存作为服务策略或诊断信息，不进入普通用户首屏。

## 四、目标信息架构

```text
应用栏：文档名｜中英方向｜任务状态｜帮助/账户
左侧工作坞：上传/队列｜基本选项｜预扫描摘要｜主操作
中央画布：原文页 ⇄ 译文页｜页导航｜缩放/旋转｜对象高亮
右侧检查器：目标编辑｜术语/TM｜QA 问题｜历史（专业模式）
```

响应式断点：`>=1440px` 三栏；`1024–1439px` 双画布、检查器抽屉；`768–1023px` 原译文切换；`<768px` 单画布和全屏抽屉。窄屏不能通过压缩字体或强行挤栏解决。

## 六、总验收标准

- 真实运行时与修改代码一致；没有“Vue 本地通过但线上仍是 Gradio旧界面”的假通过。
- PDF、DOCX、图片、PPT/PPTX 至少各有一条上传→预扫描→翻译→预览→下载闭环。
- 预扫描摘要中的页数、Figure、Table、可译图片、参考文献保护范围与 Manifest 一致。
- 单栏、双栏、多栏、旋转表、图表混排、无标题图片、纯图片页和跨页对象均能定位；不依赖百分比滚动作为唯一同步方式。
- 表格单元格和脚注、图片文字框有专用审校入口；字号过大、过小、溢出或未翻译均形成可定位 QA。
- 参考文献整区原样保留，章节标题和文章标题不被翻译；界面显示跳过理由。
- 原文不可编辑；译文修改可撤销；导出显示正式版/审阅稿、未解决问题和可编辑性。
- `queued/scanning/translating/rendering/review_ready/succeeded/failed/cancelled/blocked/degraded` 状态不互相伪装。
- 320、768、1024、1440px 下无水平溢出、译文栏裁切、工具遮挡或不可操作控件。
- 键盘可完成核心流程，焦点可见，图标有名称，状态不只依赖颜色。
- 真实样本和自动化结果写入 `WT-050g`，未解决风险和回滚步骤明确。

## 七、度量与风险

| 指标 | 目标 |
| --- | --- |
| 首次上传到预扫描摘要 | 用户可理解，不依赖技术日志；长于 1 秒有阶段反馈 |
| Manifest/UI 计数一致性 | 100%；未知/截断不得显示 0 |
| 页面/对象定位 | 金样对象点击后原译文双侧定位一致 |
| QA 可执行性 | 每条阻断问题可跳转、解决/忽略并记录理由 |
| 响应式 | 320/768/1024/1440 四档核心流程通过 |
| 可恢复性 | 刷新、断线、取消、重试不重复任务、不覆盖新代际 |

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 真实 UI 运行时不明确 | 改错代码，线上无变化 | 050a 以服务入口、资源和浏览器证据为门 |
| Manifest 字段缺失或版本漂移 | UI 猜状态、伪计数 | 适配层校验版本，缺字段 fail-closed |
| Gradio/Vue 双轨 | 视觉和交互长期分叉 | 明确唯一生产施工面，另一套只保留迁移边界 |
| 双画布性能过重 | 用户等待和滚动卡顿 | 低清占位、300 DPI 按需加载、可视页渲染、单源轮询 |
| 专业能力过载 | 快速用户无法完成任务 | 快速/专业模式和渐进披露 |
| 生产补丁覆盖 | 新界面部署后消失 | 补丁顺序签名、幂等检查、烟囱与回滚 |

## 八、批准门

用户批准 PLAN-050 后，按 050a 至 050g 顺序执行。任何子计划不得绕过运行时基线直接修改界面；任何“完成”报告必须包含自动门、真实运行时截图和样本证据。
